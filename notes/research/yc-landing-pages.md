# What Atrax can learn from YC developer-tool landing pages

Research date: 2026-09-16. Decision ticket: [What can Atrax learn from YC developer-tool landing pages?](https://github.com/rishabhsai/atrax/issues/20), under [Find Atrax's simple agent-first website and onboarding direction](https://github.com/rishabhsai/atrax/issues/19).

## Recommendation

Restore the user's original straightforward hero. Put a readable agent task and the verified CLI command together immediately below it. Follow with short capability statements. Keep branch artwork at the outer edges, subordinate to the words and controls.

The useful references are specific. Resend supplies brevity, Freestyle supplies a visible agent prompt, and Supabase supplies concise descriptions of infrastructure capabilities. This is a design recommendation based on the inspection below. It is not evidence that these patterns improve conversion.

The user has already set the direction on the hero, no eyebrow labels, general capabilities, and tree artwork. This audit informs execution of that direction. It does not replace those preferences with a composite of other brands.

## Rendered observations

### Firecrawl

White paper, orange emphasis, a centered two-line headline, and a faint technical grid. Pale texture frames the central controls. A product input sits directly below the actions. The agent-setup button changes to a copied confirmation when clicked; I did not verify its clipboard payload. Lower sections expose CLI and MCP options.

At 390 pixels, the announcement takes several lines, actions stack, and the input remains usable in the visible composition. The surrounding grid becomes less prominent. Borrow the clear center and agent action. Avoid its numerous numbered dividers, small labels, and promotional strips for Atrax. [Page, 2026-09-16](https://www.firecrawl.dev/). [Desktop](assets/yc/firecrawl-desktop.jpg), [mobile](assets/yc/firecrawl-mobile.jpg), [copy feedback](assets/yc/firecrawl-desktop-setup.jpg).

### Resend

A black field, oversized serif headline on the left, and a dark animated cube on the right. The supporting copy has two short sentences. One filled action and a quieter documentation link establish priority. Customer logos precede the code section.

On mobile, the cube moves above the headline, spending substantial height before the message. Atrax should borrow the brevity and action hierarchy. Its warm paper, existing type families, and proposed branch art need their own composition. Resend's dramatic cube is a poor match for Atrax's quiet infrastructure direction. [Page, 2026-09-16](https://resend.com/). [Desktop](assets/yc/resend-desktop.jpg), [mobile](assets/yc/resend-mobile.jpg).

### Trigger.dev

A dark full-width hero uses lime for the principal action. Dim angled terminal imagery occupies the upper area. The statement and supporting paragraph sit centrally; a horizontal strip of scenarios leads into code paired with an explanation. A demonstration follows below.

The phone layout preserves a tall decorative gap and pushes most code beneath the initial viewport. This is useful evidence for separating broad positioning from detailed proof. Atrax does not need this volume of tabs, code, or technical vocabulary in its hero. [Page, 2026-09-16](https://trigger.dev/). [Desktop](assets/yc/trigger-desktop.jpg), [code section](assets/yc/trigger-desktop-below.jpg), [mobile](assets/yc/trigger-mobile.jpg).

### Instant

A warm peach field frames a centered heading, a capability sentence, and a large founder-video thumbnail. The shutdown notice is immediately visible. Below the investor material, the site explains CLI operation, compact APIs, and undo before enumerating backend capabilities.

Mobile keeps the same sequence and readable line lengths. The main lesson is that the category can stay broad while the following sentence names what comes included. Investor portraits and a large video would delay Atrax's requested prompt and CLI. [Page, 2026-09-16](https://www.instantdb.com/). [Desktop](assets/yc/instant-desktop.jpg), [mobile](assets/yc/instant-mobile.jpg).

### Freestyle

A pale field surrounds large centered type. Floating cubes stay mostly outside the central reading area. Short capability headings have single-sentence descriptions. A later blue panel shows an entire agent task with a copy control:

> Onboard onto Freestyle.sh, build an integration with it on a branch, tell me how it did.

The desktop panel pairs its heading and task; mobile stacks them and leaves the task readable. The visible words explain what the agent should accomplish. This directly supports Atrax's requested prompt. Borrow that behavior and the clear center; exclude the 3D cubes and their large mobile footprint. [Page, 2026-09-16](https://www.freestyle.sh/). [Desktop prompt](assets/yc/freestyle-desktop-prompt.jpg), [mobile prompt](assets/yc/freestyle-mobile-prompt.jpg).

### Supabase

The inspected page uses white, black, and green. The desktop hero splits the headline/actions and capability sentence into two columns. An unequal grid immediately names the database, authentication, functions, and other services. Line illustrations support those descriptions.

At phone width the hero stacks, and the illustrated cards become compact text blocks. Several capabilities remain visible without navigating tabs. Atrax can use similarly short descriptions without reproducing the card grid. Its names should clarify jobs the platform performs, with fuller examples available farther down. [Page, 2026-09-16](https://supabase.com/). [Desktop](assets/yc/supabase-desktop.jpg), [mobile](assets/yc/supabase-mobile.jpg).

### Kernel

Cream paper, very large lowercase type, an oversized wordmark, thin rules, and square controls make the page distinctive. The hero separates the user's work from the browser infrastructure. Illustrated capability panels and benchmark material follow.

On the phone, the headline takes five large lines and the navigation anchors at the bottom. The actions still appear in the captured viewport, but the type consumes much of it. Borrow the clear responsibility statement. Avoid the oversized wordmark, forced lowercase voice, and expansive mobile headline in Atrax. [Page, 2026-09-16](https://www.kernel.sh/). [Desktop](assets/yc/kernel-desktop.jpg), [mobile](assets/yc/kernel-mobile.jpg).

### PostHog

A simulated desktop contains a scrollable window, illustrated wallpaper, icon navigation, a setup panel, and rotating product demonstrations. Clicking its AI-install button reveals a CLI command beneath the same panel. This is a command entry point, unlike Freestyle's visible natural-language task.

The phone layout retains the window treatment. A cookie notice obscures the lower setup controls in the initial capture. Keep the useful grouping of onboarding options; avoid the nested scrolling, desktop metaphor, rotating demonstrations, and competing decoration for Atrax. [Page, 2026-09-16](https://posthog.com/). [Desktop](assets/yc/posthog-desktop.jpg), [revealed command](assets/yc/posthog-desktop-install.jpg), [mobile](assets/yc/posthog-mobile.jpg).

## Transfer to Atrax

These are recommendations, not measured findings about user behavior.

1. Keep the original hero and one supporting sentence. Resend and Freestyle establish the category quickly. Atrax's supporting line should explain that it runs business apps and includes their data, access, files, and agent operations. Tie public wording to verified launch behavior. [Resend](https://resend.com/), [Freestyle](https://www.freestyle.sh/), [Atrax scope](../launch-scope.md).
2. Make the agent task visible before copying. Give it a clear copy control, with the verified CLI command next to it on desktop and immediately after it on phones. Freestyle makes the task readable; PostHog groups installation with signup. Their pages support these individual ideas. This sample does not establish a standard side-by-side prompt-and-CLI layout. [Freestyle](https://www.freestyle.sh/), [PostHog](https://posthog.com/).
3. Describe capabilities in short general sentences. Supabase shows that a broad platform can explain its component jobs without starting with a business story. Atrax can name hosting, data, access, connected apps, and shared knowledge, then provide a concise explanation of each. The user's preference for general copy remains decisive. [Supabase](https://supabase.com/), [Atrax vocabulary](../../CONTEXT.md).
4. Reserve a clear reading area for the hero and setup controls. Firecrawl's pale peripheral texture and Freestyle's peripheral objects demonstrate this compositional principle. Branches entering from the edges are Atrax's own application of it. Use low contrast, sparse detail, and tighter crops on phones. Keep artwork outside text and copy controls. [Firecrawl](https://www.firecrawl.dev/), [Freestyle](https://www.freestyle.sh/).
5. Remove eyebrow labels because the user asked for that cleaner hierarchy. This is compatible with several inspected heroes, but the sample also contains announcement pills and many section labels. There is no evidence here that removing all labels improves conversion. Useful control labels still belong beside their controls.

Do not import competitors' customer counts, logos, benchmarks, superlatives, or service promises. Do not infer agent onboarding from a button's name. Atrax's prompt and command must each complete the promised path before publication. Code, artwork generation, product changes, and deployment are outside this research ticket.
